[Сетевая модель ](https://spacelift.io/blog/docker-networking)[Docker](https://spacelift.io/blog/docker-networking) изолирует ваши контейнеры от вашей хост-системы. Контейнеры существуют в собственных сетевых пространствах имен и имеют отдельный диапазон портов.

## Что такое раскрытие порта в Docker?

Выставление порта Docker означает объявление его активно используемым контейнеризированной рабочей нагрузкой. Docker показывает информацию о портах, которые выставляют контейнеры, позволяя вам решить, какие порты вы привяжете к своему хосту.

Важно понимать, что **предоставление порта не означает его автоматическую публикацию на вашем хосте** . В Docker открытые порты — это просто метаданные. Они документируют порты, которые прослушивают контейнерные приложения.

Например, Dockerfile для веб-сервера может включать следующую инструкцию:

```bash
EXPOSE 80
```

Это означает, что приложение, работающее в контейнере, прослушивает порт 80, поэтому пользователь должен привязать этот порт к своему хосту, чтобы получить доступ к серверу извне контейнера. Однако эта инструкция не приводит к *автоматической* привязке порта при запуске контейнера.

Для некоторых новичков Docker раскрытие портов может показаться излишним, поскольку вы можете публиковать порты, не раскрывая их предварительно. Тем не менее, раскрытие остается важным механизмом документирования, который упрощает управление и обоснование ваших контейнеров.

Списки открытых портов мгновенно сообщают вам, какие порты *следует* привязать к контейнеру, а также показывают любые порты хоста, которые были без необходимости назначены контейнерам, которые не будут их использовать. Также можно автоматически публиковать все открытые порты при запуске контейнера, что экономит время при развертывании новых экземпляров приложений.

### Раскрытие порта против публикации порта

Как мы уже отметили выше, раскрытие порта — это пассивное действие, которое просто указывает на то, что контейнер способен прослушивать этот порт. Внешние коммуникации с портом должны быть отдельно включены путем публикации его на вашем хосте. Этот процесс сопоставляет номер порта хоста с портом внутри контейнера.

Пользователи и другие руководства часто смешивают эти процессы. Публикация порта часто описывается как его «раскрытие», поскольку это делает порт доступным через сетевой стек вашего хоста. Однако эта терминология неточна, поскольку она упускает из виду возможность либо раскрытия порта Docker без его публикации, либо публикации порта, который не раскрыт.

- **Укажите порт:** установите метаданные, указывающие, что приложение или служба в контейнере будут прослушивать этот порт.
- **Публикация/привязка порта:** назначение порта хоста порту контейнера, что позволит вам взаимодействовать с контейнером через сетевой интерфейс вашего хоста.

Теперь давайте рассмотрим несколько примеров раскрытия и публикации портов Docker.

## Как открыть порт в Dockerfile

Существует два основных способа предоставления порта в Docker: либо в [Dockerfile](https://spacelift.io/blog/dockerfile) , используя [инструкцию,](https://docs.docker.com/engine/reference/builder/#expose) показанную выше, либо установив флаг при запуске контейнера с помощью .[`EXPOSE`](https://docs.docker.com/engine/reference/builder/#expose)`--expose``docker run`

Чтобы открыть порт с помощью Dockerfile, вам следует использовать инструкцию для каждого порта, который вы хотите объявить.`EXPOSE`

```bash
EXPOSE 80
```

По умолчанию порт будет открыт с TCP. Вы можете открыть UDP, явно запросив его:

```bash
EXPOSE 80/udp
```

Чтобы открыть порт с TCP и UDP, повторите инструкцию дважды, по одному разу для каждого режима:`EXPOSE`

```bash
EXPOSE 80/tcp
EXPOSE 80/udp
```

Docker автоматически предоставит доступ ко всем перечисленным портам при запуске новых контейнеров из образа Docker, использующего инструкции в своем Dockerfile.`EXPOSE`

## Как раскрыть порты при создании Docker-контейнера

Иногда вам может понадобиться вручную открыть порт при запуске контейнера. Вы можете сделать это, передав флаг вашей команде.`--expose``docker run`

```bash
$ docker run my-container:latest --expose 80
```

Вы можете повторить флаг, чтобы раскрыть несколько портов. Аналогично инструкции, показанной выше, вы также можете запросить раскрытие TCP и/или UDP, используя синтаксис и . Если указан только номер порта, выбирается TCP.`EXPOSE``<port>/tcp``<port>/udp`

На практике используется редко. Порты, которые может прослушивать контейнер, обычно соответствуют портам, определенным в Dockerfile образа. Установка дополнительных портов при запуске контейнера обычно бесполезна, поскольку они не будут иметь никакого эффекта, если приложение фактически не использует эти порты.`--expose`

## Открытие портов Docker — пример

Вот краткая демонстрация, которая покажет вам, как открыть порты и проверить их значения.

### Открытие портов с помощью Dockerfile EXPOSE

Ниже приведен простой Dockerfile, определяющий образ с открытым портом:

```bash
FROM alpine:latest
EXPOSE 80
CMD ["sleep", "300"]
```

Создайте свой образ, а затем запустите из него контейнер:

```bash
$ docker build -t demo-image:latest .
$ docker run -d --name demo demo-image:latest
```

### Использование Docker run expose

Если у вас нет контроля над Dockerfile образа, вы можете вручную предоставить порты при запуске контейнера:

```bash
$ docker run -d --name demo-run --expose 443 demo-image:latest
```

### Просмотр открытых портов

Чтобы увидеть порты, доступные для контейнера, используйте команду:`docker ps`

```bash
$ docker ps
CONTAINER ID   IMAGE               COMMAND       CREATED              STATUS                  PORTS             NAMES
2fdfd038a368   demo-image:latest   "sleep 300"   2 seconds ago        Up Less than a second   80/tcp, 443/tcp   demo-run
dd50cd05e515   demo-image:latest   "sleep 300"   About a minute ago   Up About a minute       80/tcp            demo
```

## Как открыть несколько портов Docker

Будут отображены контейнеры, работающие на вашем хосте. Порты, которые каждый контейнер открыл, показаны в столбце вывода.`PORTS`

Как мы видели выше, вы можете предоставить несколько портов для контейнера, повторив инструкцию Dockerfile или флаг для .`EXPOSE``--expose``docker run`

В случаях, когда и применяются к одному контейнеру, все указанные порты будут раскрыты. Вы можете увидеть это в демонстрационном выводе docker ps выше, где контейнер раскрывает как порт 80 (из Dockerfile своего образа), так и порт 443 (из командной строки).`EXPOSE``--expose``demo-run``docker run`

## Как опубликовать открытые порты

Открытые порты должны быть опубликованы на вашем хосте, прежде чем внешний трафик сможет достичь вашего контейнера. Вам необходимо сопоставить порты контейнера с номерами портов хоста. Это достигается с помощью флага для :`-p``docker run`

```bash
$ docker run -d --name nginx -p 80:80 nginx:latest
```

В этом примере порт 80 вашего хоста сопоставляется с портом 80 внутри контейнера. Затем вы можете получить доступ к контейнерному приложению, используя сетевой интерфейс вашего хоста:

```bash
$ curl http://localhost:80
<!DOCTYPE html>
<html>
<head>
<title>Welcome to nginx!</title>
```

Опубликованные порты отображаются в столбце вывода команды. В отличие от открытых портов, которые показывают только номер порта, используемый контейнером, например, опубликованные порты показывают сопоставление между портом хоста и портом контейнера:`PORTS``docker ps``80/tcp`

```bash
$ docker ps
CONTAINER ID   IMAGE          COMMAND                  CREATED             STATUS             PORTS                               NAMES
cafc1f042132   nginx:latest   "/docker-entrypoint.…"   About an hour ago   Up About an hour   0.0.0.0:80->80/tcp, :::80->80/tcp   nginx
```

### Переназначение опубликованных портов

Порт, который вы назначаете с вашего хоста, не обязательно должен быть тем же самым, который слушает контейнер. В этом примере вы используете порт хоста 8080 для подключения к порту контейнера 80:

```bash
$ docker run -d --name nginx -p 8080:80 nginx:latest
$ curl http://localhost:8080
<!DOCTYPE html>
<html>
<head>
<title>Welcome to nginx!</title>
```

### Публикация портов на определенном интерфейсе хоста (например, localhost)

Примеры публикации портов, показанные выше, привязывают порт контейнера ко всем сетевым интерфейсам на вашем хосте. Это делает контейнер доступным для других устройств в вашей сети.

Это может быть риском безопасности для служб, которые должны быть доступны только соседям, работающим непосредственно на вашем хосте. К счастью, вы можете публиковать порты для определенных интерфейсов хоста, используя синтаксис:`host_address:host_port:container_port`

```bash
$ docker run -d --name nginx -p 127.0.0.1:8080:80 nginx:latest
```

В этом примере порт 8080 на хосте Docker (т. е. localhost) сопоставлен с портом 80 в контейнере. Трафик, поступающий на порт с другого IP-адреса, например, с публичного сетевого интерфейса вашего хоста, не достигнет контейнера.`127.0.0.1`

### Автоматическая публикация открытых портов

До сих пор наши демонстрации портов и публикации были полностью независимы друг от друга. Мы выставляли порты и публиковали их, используя два ручных шага. Вы можете опубликовать любой порт — независимо от того, выставлен он или нет — или вы можете не публиковать уже выставленные порты.

Однако, поскольку предоставление порта означает, что контейнер его использует, в большинстве случаев вам захочется опубликовать все порты, которые предоставляет контейнер. Вы можете добиться этого при запуске контейнера с помощью docker run , установив флаг ( ):`-P``--publish-all`

```bash
$ docker run -d -P --name demo demo-image:latest
```

Это позволяет избежать необходимости проверять, какие порты выставляет образ, а затем публиковать их вручную с явными флагами -p . Параметр «опубликовать все» случайным образом сопоставляет порт хоста с каждым из выставляемых портов контейнера.

Вывод контейнера подтвердит, какие сопоставления портов были назначены:`docker ps`

```bash
$ docker ps
CONTAINER ID   IMAGE               COMMAND                  CREATED             STATUS             PORTS                                     NAMES
d66f376e3860   demo-image:latest   "sleep 300"              2 seconds ago       Up 1 second        0.0.0.0:32768->80/tcp, :::32768->80/tcp   demo
```

Порт контейнера 80, определенный в инструкции в нашем демонстрационном Dockerfile, был случайным образом назначен порту хоста из-за запуска контейнера с включенным флагом -P .`EXPOSE``32768`

## Ключевые моменты

В этой статье мы рассказали вам, как выставлять и публиковать порты для ваших контейнеров Docker. Подводя итог, выставляемый порт — это метаданные, которые указывают, что номер порта используется приложением в контейнере. Выставляемые порты затем публикуются для создания привязки к вашему хосту, что делает контейнер доступным.

Публикация привязки — это операция времени выполнения при запуске контейнеров, тогда как открытые порты определяются авторами образов в Dockerfiles. Понимание этого различия поможет вам правильно управлять портами в ваших контейнерах и образах Docker.
